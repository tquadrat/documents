\subsection{The Standard Doclet Tags}
Most of the contents of this chapter is quoted from the document \bdq{JavaDoc Documentation Comment Specification for the Standard Doclet (JDK 25)} \autocite{ORACLE_DOC_JAVADOC_TAG}. 

The output of the Javadoc\index{javadoc} tool is determined by the implementation of the interface \lstinline|jdk.javadoc.doclet.Doclet| \autocite{ORACLE_DOC_DOCLET_INTERFACE} that is specified on the command line for \texttt{javadoc} by the options \texttt{-doclet} and \texttt{-docletpath} \autocite{ORACLE_TOOL:javadoc:options}. The \lstinline|Doclet| implementation is also responsible for interpreting the content of the documentation comments.

If no explicit \lstinline|Doclet| class is specified on the command line, the standard doclet (provided through the class \lstinline|jdk.javadoc.doclet.StandardDoclet| \autocite{ORACLE_DOC_STANDARDDOCLET_CLASS}) is used; it understands the Javadoc tags described below, and it provides an API for additional tags.

Alternative implementations for the \lstinline|Doclet| interface may accept the same syntax as the standard doclet, they may handle the tags completely different or they can ignore them completely. However, due to the support by many tools, the syntax supported by the standard doclet has become a \textit{de facto} standard.

The following table summarizes which tags can be used in which contexts \autocite{ORACLE_DOC_JAVADOC_TAG:Where}.

%------------------------------------------------------------------------------

\begin{adjustwidth}{1cm}{1cm}
	\noindent\rule{\linewidth}{0.4pt}
	\begin{itemize}
		\item{\textit{Methods}\index{method} includes the members of annotation\index{annotation} interfaces.}
		\item{\textit{Fields}\index{field} includes the \lstinline|enum|\index{enum} values.}
		\item{\textit{Other} includes the Overview page (see \tqfullref{sec:OverviewDoc}), which is not tied to any declaration, and HTML\index{HTML} and Markdown\index{Markdown} files in \texttt{doc-files}\index{doc-files} subdirectories of a module or package directory. The Overview page is typically specified with an option to the \texttt{javadoc}\index{javadoc} command.}
	\end{itemize}
	\renewcommand{\cellalign}{tl}
	\LTXtable{\linewidth}{comments/TagUsage.tbl.tex}
\end{adjustwidth}

%--------------------------------------------------------------------

\paragraph{\lstinline|@author|}\label{sec:TagAuthor}\index{author@"@author} Usage: \lstinline|@author <name-text>|

The tag adds an \bdq{\textsf{Author:}} entry with the specified name to the generated documentation when the \texttt{-author} option is specified on the command line for the Javadoc\index{javadoc}. A documentation comment can contain multiple \nameref{sec:TagAuthor} tags. Consider to use the custom \bdq{\nameref{sec:TagExtAuthor}}\index{extauthor@"@extauthor}  tag instead.

%--------------------------------------------------------------------

\paragraph{\lstinline|@code|}\label{sec:TagCode}\index{code@"@code}  Usage: \lstinline|{@code <text>}|

This is equivalent to \lstinline|<code>{@literal text}</code>|.

It displays text in the code font without interpreting the text as HTML\index{HTML} markup or nested Javadoc tags. This enables you to use regular angle brackets (\bdq{\textless} and \bdq{\textgreater}) instead of the HTML\index{HTML} entities (\texttt{\&lt;} and \texttt{\&gt;}) in documentation comments, such as in parameter types (\texttt{<Object>}), inequalities ($3 < 4$), or arrows (\texttt{-\textgreater}).

Use the \bdq{\{\nameref{sec:TagLiteral} …\}}\index{literal@"@literal} tag if you want the same functionality without the code font. 

%--------------------------------------------------------------------

\paragraph{\lstinline|@deprecated|}\label{sec:TagDeprecated}\index{deprecated@"@deprecated}  Usage: \lstinline|@deprecated <text>|

This tag is used in conjunction with the \lstinline|@Deprecated| \autocite{ORACLE_DOC_DEPRECATED_ANNOTATION} annotation to indicate that this API should no longer be used (even though it may continue to work).

The first sentence of the text should tell the user when the API was deprecated and what to use as a replacement. Subsequent sentences can also explain why it was deprecated.

A \bdq{\{\nameref{sec:TagLink} …\}}\index{link@"@link} tag that points to the replacement API should be added where feasible.


%--------------------------------------------------------------------

\paragraph{\lstinline|@docRoot|}\label{sec:TagDocRoot}  Usage: \lstinline|{@docRoot}|

Represents the relative path to the generated document's (destination) root directory from any generated page. This tag is useful when you want to include a file, such as a copyright page or company logo, that you want to reference from all generated pages.

%--------------------------------------------------------------------

\paragraph{\lstinline|@exception|} This is a synonym for the \bdq{\nameref{sec:TagThrows}}\index{throws@"@throws} tag; it should not be used.

%--------------------------------------------------------------------

\paragraph{\lstinline|@hidden|}\label{sec:TagHidden}\index{hidden@"@hidden}  Usage: \lstinline|@hidden|

Hides a program element from the generated API documentation. This tag may be used when it is not otherwise possible to design the API in a way that such items do not appear at all.

%--------------------------------------------------------------------

\paragraph{\lstinline|@index|}\label{sec:TagIndex}\index{index@"@index}  Usage: \lstinline|{@index <word> <description>}| or\\  
\lstinline|    {@index "<phrase>"  <description>}|

Declares that a word or phrase, together with an optional short description, should appear in the index files generated by the standard doclet. The index entry will be linked to the word or phrase that will appear at this point in the generated documentation. The description may be used when the word or phrase to be indexed is not clear by itself, such as for an acronym.

%--------------------------------------------------------------------

\paragraph{\lstinline|@inheritDoc|}\label{sec:TagInheritDoc}\index{inheritDoc@"@inheritDoc}  Usage: \lstinline|{@inheritDoc}|

Inherits (copies) the documentation comment from the nearest inheritable class\index{class} or implementable interface\index{interface} into the current documentation comment at this tag's location. This enables you to write more general comments higher up the inheritance tree and to write around the copied text.

%--------------------------------------------------------------------

\paragraph{\lstinline|@link|}\label{sec:TagLink}\index{link@"@link}  Usage: \lstinline|{@link <module/package.class#member> <label>}|

Inserts an inline link with a visible text label that points to the documentation for the specified module, package, class, or member name of a referenced class. The label will be rendered in the code font, and if it is omitted, the link target is used instead.

This tag is similar to the \bdq{\nameref{sec:TagSee}}\index{see@"@see} tag. Both tags require the same references and accept the same syntax for \bdq{\texttt{<module/package.class\#member>}} and the label. The main difference is that the \bdq{\{\nameref{sec:TagLink} …\}} tag generates an inline link rather than placing the link in the \bdq{\textsf{See Also:}} section. The \bdq{\{\nameref{sec:TagLink} …\}} tag begins and ends with curly braces to separate it from the rest of the inline text. If you need to use the right curly brace (\bdq{\}}) inside the label, then use the HTML entity notation \bdq{\texttt{\&\#125;}}.

%--------------------------------------------------------------------

\paragraph{\lstinline|@linkplain|}\label{sec:TagLinkplain}\index{linkplain@"@linkplain}  Usage: \lstinline|{@linkplain <module/package.class#member> <label>}|

This tag behaves the same as the \bdq{\nameref{sec:TagLink}}\index{link@"@link} tag, except the link label is displayed in plain text rather than code font. For \bdq{\nameref{sec:TagLinkplain}}\index{linkplain@"@linkplain} the label is usually plain text, and it should considered to be mandatory.

%--------------------------------------------------------------------

\paragraph{\lstinline|@literal|}\label{sec:TagLiteral}\index{literal@"@literal}  Usage: \lstinline|{@literal <text>}| 

Displays text without interpreting the text as HTML\index{HTML} markup or nested Javadoc tags.  This enables you to use regular angle brackets (\bdq{\textless} and \bdq{\textgreater}) instead of the HTML\index{HTML} entities (\texttt{\&lt;} and \texttt{\&gt;}) in documentation comments, such as in parameter types (\texttt{<Object>}), inequalities ($3 < 4$), or arrows (\texttt{-\textgreater}).

For example, the documentation comment text \lstinline|{@literal A<B>C}| displays unchanged in the generated HTML\index{HTML} page in your browser, as \bdq{\textsf{A<B>C}}. The \bdq{\texttt{<B>}} is not interpreted as bold (and it is not in code font). 

If you want the same functionality with the text in code font, then use the \bdq{\{\nameref{sec:TagCode} …\}}\index{code@"@code} tag.

%--------------------------------------------------------------------

\paragraph{\lstinline|@param|}\label{sec:TagParam}\index{param@"@param}  Usage: \lstinline|@param <parameter-name> <description>|

Adds a parameter with the specified parameter name followed by the specified description to the \bdq{\textsf{Parameters:}} section. The parameter name can be the name of a parameter in a method or constructor, or the name of a type parameter of a class, method, or constructor. Use angle brackets (\bdq{\texttt{<…>}}) around the parameter name to indicate it as a type parameter.

%--------------------------------------------------------------------

\paragraph{\lstinline|@provides|}\label{sec:TagProvides}\index{provides@"@provides}  Usage: \lstinline|@provides <service-type> <description>|

This tag may only appear in the documentation comment inside a \texttt{module-info.java}\index{module-info.java} file. It serves to document an implementation of a service that is provided by the module. The description may be used to specify how to obtain an instance of this service provider, and any important characteristics of the provider itself. 

%--------------------------------------------------------------------

\paragraph{\lstinline|@return|}\label{sec:TagReturn}\index{return@"@return}  Usage: \lstinline|@return <description>| or\\
\lstinline|    {@return <description>}|

When used as a block tag, \bdq{\nameref{sec:TagReturn}}\index{return@"@return} adds a \bdq{\textsf{Returns:}} section with the description text to the documentation comment of a method\index{method}.

The use as an inline tag \bdq{\{\nameref{sec:TagReturn}\}}\index{return@"@return} sets the comment text to \bdq{Returns <description>.} and adds a \bdq{\textsf{Returns:}} section with the description. See page \pageref{sec:ReturnValue} with a sample on how to use this tag. 

%--------------------------------------------------------------------

\paragraph{\lstinline|@see|}\label{sec:TagSee}\index{see@"@see} \  

Adds a \bdq{\textsf{See Also:}} heading with a link or text entry that points to a reference. The tag has three variations; see the respective section in \autocite{ORACLE_DOC_JAVADOC_TAG} for the details.

When referencing a program element, the link has the same syntax as for the \bdq{\{\nameref{sec:TagLink}\}}\index{link@"@link} tag.

%--------------------------------------------------------------------

\paragraph{\lstinline|@serial|, \lstinline|@serialData|, \lstinline|@serialField|} \ 

Used in the documentation comment for a default serializable field. See \bdq{Documenting Serializable Fields and Data for a Class} \autocite{ORACLE_DOC_OBJECT_SERIALIZATION:DocumentingSerializableFieldsData} on how to use these tags.

%--------------------------------------------------------------------

\paragraph{\lstinline|@since|}\label{sec:TagSince}\index{since@"@since}  Usage: \lstinline|@since <since-text>|

Adds a \bdq{\textsf{Since:}} heading with the specified \texttt{<since-text>} value to the generated documentation. The text specifies when the respective program element was first introduced. It has no special internal structure, but it is recommended that it should be just a version number or alike. Consecutive \bdq{\nameref{sec:TagSince}}\index{since@"@since} tags can be used for additional information: 
\keeplisting{4}
\begin{lstlisting}[language=Comment]
…
*  @since 3.4.5
*  @since modified in version 3.4.7
*  @since fixed in version 4.0.0
…
\end{lstlisting}
results in
\begin{center}
	\includegraphics[scale=0.55]{comments/JavadocSince1}
\end{center}
This will be discussed again in \tqfullvref{sec:MaintenanceComments}.

%--------------------------------------------------------------------

\paragraph{\lstinline|@snippet|}\label{sec:TagSnippet}\index{snippet@"@snippet}  Usage: \lstinline|{@snippet <attributes>}|

Includes a fragment, or "snippet", of example code in the generated documentation. This tag is discussed in detail in \tqfullvref{sec:EmbeddingCodeSnippets}. 

%--------------------------------------------------------------------

\paragraph{\lstinline|@summary|}\label{sec:TagSummary}\index{summary@"@summary}  Usage:  \lstinline|{@summary <text>}|

Identifies  the summary of an API description, as an alternative to the default policy to identify and use the \textit{first sentence} of the API description. The tag only has significance when used at the beginning of a description. In all cases, the tag is rendered by simply rendering its content.

You should use the \bdq{\{\nameref{sec:TagSummary} …\}} tag always because the identification of the first sentences is unreliable under some circumstances.

%--------------------------------------------------------------------

\paragraph{\lstinline|@throws|}\label{sec:TagThrows}\index{throws@"@throws}  Usage: \lstinline|@throws <class-name> <description>|

The \bdq{\nameref{sec:TagThrows}}\index{throws@"@throws} tag adds a \bdq{\textsf{Throws:}} subheading to the generated documentation, with the \texttt{<class-name>} and the description text. The class name is the name of the exception\index{class!exception class} that might be thrown by the method\index{method}, and the description provides information about the conditions for that exception to be thrown. 

%--------------------------------------------------------------------

\paragraph{\lstinline|@uses|}\label{sec:TagUses}  Usage: \lstinline|@uses <service-type> <description>|

This tag may only appear in the documentation comment inside a \texttt{module-info.java}\index{module-info.java} file. It serves to document that a service may be used by the module. The description may be used to specify the characteristics of the service that may be required, and what the module will do if no provider for the service is available.

%--------------------------------------------------------------------

\paragraph{\lstinline|@value|}\label{sec:TagValue}\index{value@"@value}  Usage: \lstinline|{@value <format>}| or \\ 
\lstinline|    {@value <format> <module/package.class#field>}|

The \bdq{\{\nameref{sec:TagValue} …\}} tag is used either in the documentation comment for a constant\index{field!constant} to display the value of that constant\footnote{Refer to \pageref{sec:Constants} and \pageref{lbl:Constant}.} or within the documentation comment for other program elements to refer to the value of that constant.

\keeplisting{10}
Basically, this looks like this:
\begin{lstlisting}
/**
 *  The default size: {@value}.
 */
public static final int DEFAULT_SIZE = 22;

/**
 *  <p>{@summary Calculates the volume.}</p>
 *  <p>Uses the
 *  {@link #DEFAULT_SIZE}
 *  of
 *  {@value #DEFAULT_SIZE}
 *  to determine the final volume.</p>
 *
 *  @return The final volume.
 */
public final int calcVolume() { … }
\end{lstlisting}
The generated output is this:
\begin{center}
	\includegraphics[scale=0.55]{comments/JavadocValue1}
\end{center}
\begin{center}
	\includegraphics[scale=0.55]{comments/JavadocValue2}
\end{center}

The optional \texttt{<format>} argument can be used to change the appearance of the constant value. If provided, it must conform to the definition of a format string, as specified in the documentation for \lstinline|java.util.Formatter| \autocite{ORACLE_DOC_FORMATTER_CLASS}. 

%--------------------------------------------------------------------

\paragraph{\lstinline|@version|}\label{sec:TagVersion}\index{version@"@version}  Usage: \lstinline|@version <version-text>|

Adds a \bdq{\textsf{Version:}} subheading with the specified \texttt{<version-text>} value to the generated documents when the \bdq{\texttt{-version}} option is specified on the command line for the Javadoc\index{javadoc} tool. This tag is intended to hold the current revision of the program element, as opposed to the \bdq{\nameref{sec:TagSince}}\index{since@"@since} tag, which holds the release number when this code was introduced. The \texttt{<version-text>} value has no special internal structure, but it is recommended that is is a version number.

\section{Tips and Tricks}
\subsection{Special Characters}\label{sec:DocCommentSpecialChars}
The documentation comments are parsed by the Javadoc\index{javadoc} tool and then translated to HTML\index{HTML}. During that process, the comments will be scanned for the various Javadoc tags, mentioned \hyperref[sec:JavaDocTags]{above}. Additionally, the DocLint feature validates the output as proper HTML5\index{HTML}.

That means that the use of some characters in the comment text can cause problems. These characters are:

\renewcommand{\cellalign}{tl}
\LTXtable{\linewidth}{comments/SpecialChars.tbl.tex}

There are different solutions for the individual characters, depending on the context:
\begin{itemize}
	\item{In most cases, the inline Javadoc tag \bdq{\{\nameref{sec:TagLiteral}\}}\index{literal@"@literal} helps; with the exception of the closing curly brace(\bdq{\texttt{\}}}) and \bsq{\texttt{*/}}, the text within the tag is displayed in the generated documentation exactly as specified.}

	\item{For 
	\bsq{\texttt{\textless}}, 
	\bsq{\texttt{\textgreater}}, 
	\bsq{\texttt{\&}}, 
	\bsq{\texttt{@}}, 
	\bsq{\texttt{"}} and 
	\bsq{\texttt{*/}}, you can use the 
	HTML\index{HTML} entities: 
	\bdq{\texttt{\&lt;}}, 
	\bdq{\texttt{\&gt;}}, 
	\bdq{\texttt{\&amp;}}, 
	\bdq{\texttt{\&\#64;}}, 
	\bdq{\texttt{\&quot;}} and 
	\bdq{\texttt{\&ast;/}} (or 
	\bdq{\texttt{\&\#42;/}}), but of course not inside a 
	\bdq{\{\nameref{sec:TagLiteral}\}}\index{literal@"@literal} or 
	\bdq{\{\nameref{sec:TagCode}\}}\index{code@"@code} tag.}

	\item{If you need text in code font that should contain the closing curly brace (\bsq{\texttt{\}}}), you cannot use the \bdq{\{\nameref{sec:TagCode}\}}\index{code@"@code} tag; instead you must wrap it in the HTML\index{HTML} \lstinline|<code>| tag.}

	\item{Text in code font that must contain HTML\index{HTML} entities (like \bdq{\texttt{\&ast;/}} for \bsq{\texttt{*/}}) must be wrapped HTML\index{HTML} \lstinline|<code>| tag, too.}

	\item{If you need to use the right curly brace (\bdq{\texttt{\}}}) inside the link label of a \bdq{\{\nameref{sec:TagLink}\}}\index{link@"@link} or \bdq{\{\nameref{sec:TagLinkplain}\}}\index{linkplain@"@linkplain} tag, then use the HTML\index{HTML} entity notation \bdq{\texttt{\&\#125;}} for it.
	
	You can also use other HTML\index{HTML} entities inside those link labels, like \bdq{\texttt{\&ast;/}} for \bsq{\texttt{*/}}, or \bdq{\texttt{\&\#64;}} for \bsq{\texttt{@}}; the latter is quite often used when refering to an annotation\index{annotation} class:
	
\keeplisting{4}
\begin{lstlisting}[language=Comment]
*  …
*  {@link Override &#64;Override}
*  …
\end{lstlisting}}
\end{itemize}

\subsection{Embedding Code Snippets}\label{sec:EmbeddingCodeSnippets}
Sometimes it is helpful to embed code into the generated documentation, either as a sample on how a method is used, a snippet that explains the implementation, a script that is used to start the program, or a section from a configuration file.

This can be achieved in several ways, described below.

\subsubsection{Plain HTML}\index{HTML}
The fastest approach for embedding a code snippet into the generated documentation is to use the HTML\index{HTML} tags \bsq{\texttt{<pre>}} and \bsq{\texttt{<code>}} for it:
\keeplisting{8}
\begin{lstlisting}[language=Comment]
 …
 *  <pre><code>public final String supplier()
 *  {
 *    /*
 *     * Return the constant value.
 *     &ast;/
 *    return "value";
 *  }  //  supplier()</code></pre>
 …
\end{lstlisting}

That looks like this:
\begin{center}
	\includegraphics[scale=0.55]{comments/JavadocPreCode1}
\end{center}

The command line option \mbox{\bsq{\texttt{-{}-syntax-highlight}}} enabled syntax highlighting here.

\keeplisting{8}
This is how the documentation of the \Java API does it:
\begin{lstlisting}[language=Comment]
 …
 *  <hr>
 *  <div class="source-container"><pre>public final String supplier()
 *  {
 *    /*
 *     * Return the constant value.
 *     &ast;/
 *    return "value";
 *  }  //  supplier()</pre></div>
 *  <hr>
 …
\end{lstlisting}

\keeplisting{9}
It allows to add line numbers to the code snippet:
\begin{lstlisting}[language=Comment]
 …
 *  <hr>
 *  <div class="source-container"><pre><span class="source-line-no">01</span>public final String supplier()
 *  <span class="source-line-no">02</span>{
 *  <span class="source-line-no">03</span>  /*
 *  <span class="source-line-no">04</span>   * Return the constant value.
 *  <span class="source-line-no">05</span>   &ast;/
 *  <span class="source-line-no">06</span>  return "value";
 *  <span class="source-line-no">07</span>}  //  supplier()</pre></div>
 *  <hr>
 …
\end{lstlisting}

This would be the result:
\begin{center}
	\includegraphics[scale=0.55]{comments/JavadocPreCode2}
\end{center}
 

\subsubsection{The Javadoc Tag \bsq{\{@snippet\}}}
The tag \bdq{\{\nameref{sec:TagSnippet} …\}}\index{snippet@"@snippet} was introduced for the Javadoc\index{javadoc} tool with Java~18, and it was specified through JEP 413 \autocite{JEP413}. It allows several options to shape the embedded code snippet, including syntax highlighting. The documentation in \autocite{ORACLE_DOC_JAVADOC_TAG} for this tag is insufficient (at best), I recommend these articles if you want to dive deeper into possibilities of that tag: \autocite{Baeldung:CodeSnippets,ORACLE_DOC_JAVADOC_GUIDE:Snippets,Korando:CodeSnippets}.

The line below includes the contents of the file \texttt{sample.html} into the generated documentation through the standard Javadoc\index{javadoc} \bdq{\{\nameref{sec:TagSnippet} …\}}\index{snippet@"@snippet} tag:
\keeplisting{5}
\begin{lstlisting}[language=Comment]
 …
 *  <hr>
 *  {@snippet file="sample.html"}
 *  <hr>
 …
\end{lstlisting}

\keeplisting{7}
It also allows to embed the code snippet directly into the documentation comment:
\begin{lstlisting}[language=Comment]
 …
 *  <hr>
 *  {@snippet :
 *  <h3>Included Section</h3>
 *  <p>This section was included from an external file through the {@snippet} tag.</p>
 *  <p>It does allow to place code snippets into the generated documentation; it is not limited to HTML or Java.</p>}
 *  <hr>
 …
\end{lstlisting}

The result looks like this\footnote{Compare this with the output from the \bdq{\{\nameref{sec:TagInclude}\}} tag on page \pageref{sec:TagInclude}.}:
\begin{center}
	\includegraphics[scale=0.55]{comments/JavadocSnippet1}
\end{center}

\subsubsection{The Custom Tag \bsq{\{@include\}}}
The custom tag \bdq{\{\nameref{sec:TagInclude}\}} is part of \bdq{tquadrat’s Javadoc Extensions} (or short \bsq{foundation-javadoc}), my Javadoc extensions library that I described already in \tqfullref{sec:CustomTaglets}. It can be found at \autocite{TQUADRAT_ORG_FOUNDATION_JAVADOC}.

To embed code snippets, you would usually use the process-mode \texttt{SOURCE} or the previously not mentioned process-mode \texttt{SOURCE\_SNIPPET}.

The latter allows that just specified parts of a source file are included into the documentation.

Aside the different presentation, the main differences between the \bdq{\{\nameref{sec:TagInclude}\}} tag with process-mode \texttt{SOURCE} and the standard tag
\bdq{\{\nameref{sec:TagSnippet}\}}\index{snippet@"@snippet} are that the latter comes with a copy link, while it does not allow for line numbers.
 
For more details on the \bdq{\{\nameref{sec:TagInclude}\}} tag, refer to \autocite{TQUADRAT_ORG_FOUNDATION_JAVADOC}.

\subsection{IDE Support}
Eclipse can be configured in a way that it will issue warnings or even errors for missing documentation comments: see \texttt{Window | Preferences | Java | Compiler | Javadoc}.

To achieve the same for IntelliJ IDEA, you go to \texttt{File | Settings}, and there you select \texttt{Editor | Inspections > Java > Javadoc}.

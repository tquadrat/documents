\subsection{The Constructor Comment}\label{sec:ConstructorComment}
In principle, a constructor\index{constructor} is simply a special form of a method\index{method}, albeit one without a return value. Consequently, the rules for documenting a method\index{method} also apply to documenting a constructor\index{constructor}.

However, since all constructors\index{constructor} essentially do the same thing – creating an instance of the class in which they are defined – you can actually use the same comment text every time, and it does not matter whether the constructor\index{constructor} is public, protected or private:
\keeplisting{4}
\begin{lstlisting}[caption={Simple Constructor}]
/**
 *  Creates a new instance of {@code MyClass}.
 */
public MyClass() { /* Does nothing */ }
\end{lstlisting}

Of course, this comment does not say that much, but a constructor is not doing much more than instantiating the class instance, and that is very obvious. You do not need to add that the (default) constructor\index{constructor} is empty; it is sufficient that this is documented in the body. 

You can modify or enhance the suggested comment text according your needs. So if the constructor\index{constructor} has side effects, these should be described properly. But in general, a constructor\index{constructor} should not have any side-effects at all. 

A class that does have only static methods\index{method}\footnote{Such a class is called a \bdq{Utility Class}\index{class!utility class}; refer to \tqfullvref{sec:UtilityClasses} for more details.} should have a private constructor like this:\footnote{The class for the \lstinline|Error|\index{class!class!error class} used in the \lstinline|throw| statement is described in \autocite{TQUADRAT_ORG_FOUNDATION_PRIVATECONSTRUCTORFORSTATICCLASSCALLEDERROR}.}
\keeplisting{5}
\begin{lstlisting}[caption={Utility Class Constructor}]
/**
 *  No instance is allowed for class {@code MyUtilityClass}.
 */
private MyUtilityClass() 
{ 
    throw new PrivateConstructorForStaticClassCalledError( MyUtilityClass.class ); 
}   // MyUtilityClass()
\end{lstlisting}

The parameters of a constructor\index{constructor} must be documented in the same way as that for a method\index{method}, with the \bdq{\nameref{sec:TagParam}}\index{param@"@param}. If the constructor\index{constructor} modifies one of its arguments, this is a serious side effect and needs to be documented – refer to chapter \tqfullvref{sec:MutableTypesForArguments} for more details.

Although constructors\ should not throw (checked) exceptions, sometimes it could not be avoided without overcomplicating the API of a class. In such case, all exceptions has to be listed with the \bdq{\nameref{sec:TagThrows}}\index{throws@"@throws} tag and a description of the conditions for the particular exception. Refer also to chapter \tqfullvref{sec:GeneralExceptionHandling} for some more details on exception handling.
